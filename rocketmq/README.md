# RocketMQ 实验模块

在仓库根目录执行 `mvn -pl rocketmq test` 可运行不依赖 Broker 的回归测试。
启动应用前需按 `docker/docker-compose.yml` 准备 RocketMQ 环境，应用默认端口为 8082。

## 参数约束

接口路径保持不变；非法参数返回 HTTP 400，不再静默截断数值或切换到默认实验模式。

| 参数 | 范围 |
| --- | --- |
| 事务 `mode` | `commit` / `rollback` / `unknown` |
| 重试 `mode` | `flap` / `always` |
| `duplicates`、`orders` | 1–1000 |
| 积压实验 `count` | 1–50000 |
| 慢消费 `millis` | 0–2000 |
| `sku`、支付 `orderId` | 非空白 |

## 观察实验结果

- 事务 `unknown` 模拟本地事务已成功、确认超时；重复回查均读取相同结果。事务监听器收到的是字节消息体，使用 UTF-8 解码。
- 订单支付和超时取消竞争 `UNPAID` 状态，只有一方可以成功；重复消息不会修改终态。
- 重试实验使用消息携带的 `reconsumeTimes`，不依赖当前实例的本地尝试次数。
- 积压 stats 是本进程累计计数，收发差值可能为负，不能代替消费组 lag；实际积压请查看 Dashboard。
- 原生客户端最多等待 10 秒确认本轮消息在当前实例被消费，超时会明确提示，不会报告一发一收成功。

订单、事务和去重集合仍是教学用内存状态，重启丢失，也不跨实例共享。
延迟订单的建单与发消息不是原子操作，发送失败需补偿；生产环境需要持久化和可靠投递方案。
